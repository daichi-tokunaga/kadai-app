<h1>初回のみやること</h1>

このリポジトリ(徳永のアカウントにあるリポジトリ)を自身のアカウントにフォークして課題を進めること。

<h2>フォーク手順</h2>

1. https://github.com/daichi-tokunaga/kadai-app/fork にアクセス

1. Ownerが自分のアカウント、Repository nameがkadai-appになっていることを確認

1. 画面下のCreate fork(緑のボタン)を押下

1. 自身のアカウントにコピーされるので以降、そこに作ったものをpushしていく


<h1>環境構築(毎回やること)</h1>

> ### この教室の PC は、シャットダウンするとデータベースが消えます
>
> そのため、**授業のたびにこの環境構築を最初からやり直すことになります。**
> 「前回は動いたのに `Unknown database 'kadai-app'` と言われる」のはこれが原因です。
>
> **書いたコードも一緒に消えます。**
> 帰る前に必ず自分のフォークに push すること(ページ下部の「帰る前に必ずやること」を参照)。

<h2>0. まず MySQL を起動する</h2>

XAMPP のコントロールパネルを開き、**MySQL の行の Start** を押す。
「Running」と緑色になれば起動している。

> アプリ自体は `php artisan serve` で動くため Apache は不要。
> phpMyAdmin でデータベースの中身を見たいときだけ Apache も起動する。

**MySQL を起動せずに先へ進むと、手順 4 で必ず失敗する。**

<h2>1. 準備</h2>

1. 自身のgithubアカウントからリポジトリをcloneしVSCodeで開く

```
git clone <自分のフォークのURL> kadai-app
```

> **2 回目以降の人へ**
> 徳永のリポジトリではなく、**前回 push した自分のフォーク**を clone すること。
> 徳永のリポジトリを clone すると、前回の作業が入っていない状態から始まってしまう。

1. VSCode上で[ctrl + @]でターミナルを開く(以降コマンドはここで入力する)(コマンドプロンプトでも可)

以降のコマンドはすべて `kadai-app` フォルダの中で実行する。

<h2>2. プロジェクトのアップデート</h2>

コマンドを実行

```
composer install
```

> 3〜5 分かかる。`vendor` フォルダはリポジトリに含まれていないため、毎回これが必要。

<h2>3. 環境設定ファイルの作成</h2>

このアプリはデータベースの接続先などの設定を `.env` ファイルから読み込む。
`.env` は環境ごとに内容が変わるためリポジトリには含まれておらず、自分で用意する。

1. `composer install` を実行すると `.env.example` がコピーされて `.env` が作られる。
作られていない場合は手動でコピーする

```
copy .env.example .env
```

1. アプリケーションキーを発行する

```
php artisan key:generate
```

> `.env` に書いたパスワードなどをうっかり公開しないため、
> `.env` は `.gitignore` に登録されている。**このファイルは commit しないこと。**

<h2>4. データベースの構築</h2>

テーブルの作成と初期データの投入を 1 コマンドで行う。

```
php artisan migrate --seed
```

実行すると下記のようにデータベースを作るか確認されるので yes と入力

```
  WARN  The database 'kadai-app' does not exist on the 'mysql' connection.

Would you like to create it? (yes/no) [no]

> yes <=入力
```

テーブルが 4 つ作られたあと、初期データが入れば成功。

```
   INFO  Running migrations.

  2014_10_12_000001_create_users_table ................... DONE
  2019_12_14_000001_create_personal_access_tokens_table .. DONE
  2022_12_12_102505_create_posts_table ................... DONE
  2022_12_12_123623_create_follows_table ................. DONE

   INFO  Seeding database.

  UserSeeder ..... DONE
  PostSeeder ..... DONE
  FollowSeeder ... DONE
```

> **データが入ったか確認したいとき**
> `php artisan tinker` を起動して下記を入力する(`exit` で抜ける)。
> ユーザー 3 件、投稿 20 件が返れば成功。
>
> ```
> User::count()
> Post::count()
> ```

<h3>データを初期状態に戻したいとき</h3>

課題を進めるうちにデータがぐちゃぐちゃになったら、下記で作り直せる。
(自分で投稿したデータなどはすべて消える)

```
php artisan migrate:fresh --seed
```

> **`migrate:fresh` はデータベースが存在しないと使えない。**
> 既存のテーブルを削除してから作り直すコマンドなので、データベース自体が無い状態で実行すると
> `SQLSTATE[HY000] [1049] Unknown database 'kadai-app'` で止まる。
>
> **PC を起動した直後は、必ず手順 4 の `php artisan migrate --seed`(`:fresh` なし)を使うこと。**
> こちらはデータベースが無ければ作るところから始めてくれる。

<h1>まとめてコピペする用(2 回目以降)</h1>

XAMPP で MySQL を Start したあと、下記をターミナルに貼り付ければ起動まで一気に進む。

<h1>帰る前に必ずやること</h1>

**この PC は電源を切るとデータベースも書いたコードも消えます。**
授業の終わりに、必ずどちらかをやること。

<h2>方法A: 自分のフォークに push する(おすすめ)</h2>

```
git add .
git commit -m "Bug1とBug2を修正"
git push origin master
```

> clone 元が自分のフォークなら `origin` がそのまま自分のリポジトリを指しているので、
> `git push origin master` だけでよい。
> 次回はこのフォークを clone すれば続きから始められる。

<h2>方法B: フォルダごと USB メモリやクラウドにコピーする</h2>

`kadai-app` フォルダをまるごとコピーする。
`vendor` フォルダはとても大きいので、消してからコピーしてもよい
(次回 `composer install` すれば元に戻る)。

> **どちらの方法でもデータベースの中身は保存されない。**
> 投稿したデータなどは毎回消えるが、初期データは `php artisan migrate --seed` で
> 入れ直せるので問題ない。

- - -

<h1>うまくいかないときは</h1>

| 症状 | 原因と対処 |
| --- | --- |
| `SQLSTATE[HY000] [1049] Unknown database 'kadai-app'` | データベースがまだ無い。手順 4 の `php artisan migrate --seed` を実行する(`migrate:fresh` ではなく) |
| `SQLSTATE[HY000] [2002] 接続できませんでした` | MySQL が起動していない。XAMPP で MySQL を Start する |
| `No application encryption key has been specified.` | `php artisan key:generate` がまだ |
| `.env` が見つからない | `copy .env.example .env` を実行する |
| ログイン画面が出ずエラーになる | `composer install` が途中で失敗している。もう一度実行する |
| `Failed to listen on 127.0.0.1:8000` | すでに `php artisan serve` が動いている。前のターミナルを閉じるか `php artisan serve --port=8001` |
| 前回書いたコードが無い | 自分のフォークではなく徳永のリポジトリを clone している。手順 1 を参照 |

<h1>設計メモ</h1>

課題に取り組む前に読むこと。
このアプリは Laravel の標準的な書き方に沿って作られている。
**課題の修正も、下記の書き方に合わせて実装すること。**

- - -

<h2>認証</h2>

Laravel 標準の認証機構(`Auth` ファサード)を使用している。

* `App\Models\User` は `Authenticatable` を継承している
* パスワードは `User` モデルのミューテタで自動的にハッシュ化される(平文はデータベースに入らない)
* ログイン判定は各コントローラではなく `routes/web.php` のミドルウェア(`auth` / `guest`)で行う
  ため、コントローラ内にログイン判定を書く必要はない
* ログイン中のユーザーは `Auth::user()` または `$request->user()` で取得する

- - -

<h2>認可</h2>

「本人だけができる操作」の判定はポリシーに集約している。

| ポリシー | 判定内容 |
| --- | --- |
| `App\Policies\PostPolicy` | 投稿の編集・削除は投稿者本人のみ |
| `App\Policies\UserPolicy` | プロフィール編集は本人のみ / 自分自身はフォローできない |

* コントローラ側は `$this->authorize('update', $post)` で呼び出す(違反時は 403)
* 画面側は `@can('update', $post)` で表示を切り替えられる

- - -

<h2>バリデーション</h2>

フォームリクエスト(`app/Http/Requests/`)に定義する。
コントローラの引数の型を `Request` からフォームリクエストに差し替えるだけで適用される。

| クラス | 対象 |
| --- | --- |
| `LoginRequest` | ログイン |
| `ProfileRequest` | プロフィール編集 |

エラーメッセージの表示には `<x-error-messages />` コンポーネントが使える。
`$errors` に入っているメッセージを一覧で表示する。

JavaScript 側でエラーを表示する場合は `public/js/app.js` の `renderErrors()` が使える。

> **ヒント**
> バリデーションルールを PHP と JavaScript の両方に直接書くと、片方を直し忘れて
> 食い違いが起きる。定数として一箇所に定義し、`data-*` 属性でビューから
> JavaScript に渡すようにすると二重管理を避けられる。

- - -

<h2>データベース</h2>

| テーブル | 補足 |
| --- | --- |
| `users` | |
| `posts` | `is_deleted` による論理削除 |
| `follows` | `users` の多対多の中間テーブル。`(user_id, follow_user_id)` に一意制約があり二重フォローを防ぐ |

* カラム名は Laravel の規約に合わせて `user_id` / `follow_user_id`
* 外部キー制約とインデックスを設定済み
* 文字セットは `utf8mb4`。`utf8`(utf8mb3) では絵文字が保存できず投稿時にエラーになる

<h3>リレーション</h3>

```php
$user->posts        // ユーザーの投稿 (hasMany)
$user->followings   // フォローしているユーザー (belongsToMany)
$user->followers    // フォローされているユーザー (belongsToMany)
$post->user         // 投稿者 (belongsTo)
```

一覧を表示するときは `with()` / `loadCount()` を使い、N+1 クエリを発生させないこと。

- - -

<h2>ルーティング</h2>

* ルートには名前が付いている。リンクは `href="/user/1"` ではなく
  `href="{{ route('users.show', $user) }}"` と書く
* `{user}` / `{post}` はルートモデルバインディングにより、コントローラの引数に
  モデルが直接渡される。存在しない ID は自動的に 404 になるため
  コントローラ側で存在チェックを書く必要はない

- - -

<h2>画面</h2>

* すべての画面は `resources/views/layouts/app.blade.php` を `@extends` する
* CSS は `public/css/app.css` に集約する(各 Blade に `<style>` を書かない)
* JavaScript は `public/js/app.js` に集約する
* 確認ダイアログは `<button data-confirm="...">` と書けば `app.js` が処理する

<h2>フロントエンドのビルドについて</h2>

このアプリは Vite を使っていない。CSS / JS は `public/css/app.css` と
`public/js/app.js` を Blade から直接読み込んでいる。
そのため **Node.js と npm は不要**。`npm install` は実行しなくてよい。
